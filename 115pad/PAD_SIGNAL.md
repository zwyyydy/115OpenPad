# 流水线同步信号（PAD_SIGNAL）

让你自己的刮削流水线跑完后告诉 115pad「哪些目录变了」，App 只重扫那几个目录，不必整库重扫（200+ 目录的库：约 1200 次列目录降到几次）。

- 流水线：往 115 里写一份 JSON 信号
- App：设置 → 流水线同步（默认开）按间隔轮询信号目录，读到新信号就定向扫描

## 信号文件

- 位置：`<媒体库根>/.pad_signal/`（App 自动查找；写在别处可在设置里手选）
- 文件名：时间戳，如 `20260928-103138.json` —— 按文件名排序即时间序，别改已写过的文件
- 编码：UTF-8

```json
{
  "dirs": ["/媒体库根/子目录/ABC-123 示例演员"],
  "gone": ["/媒体库根/ABC-123"]
}
```

| 字段 | 必填 | 含义 |
|---|---|---|
| `dirs` | 与 `gone` 至少一个 | 需重扫的目录（115 绝对路径，写到影片目录那一层） |
| `gone` | 否 | 已移走 / 删除的目录，App 清掉其索引 |
| `codes` / `actors` | 否 | 仅日志排查用，App 不依赖 |

## 要点

1. 路径必须落在某个媒体库根下，否则被忽略；带不带前导斜杠都行（App 按库自己的写法归一化）
2. **重刮老片也要写进 `dirs`**：App 会先清该目录的 nfo/海报缓存再重扫，不写就一直看到旧简介旧海报
3. 只放新文件（App 按文件名游标去重）；要重放就换个新文件名
4. 目录名里的空格直接写，不用转义
5. 信号文件的保留由流水线负责（建议只留最近几十份）

## 请求量与行为

- 没新信号 = 每轮 1 次列目录；有信号 = 每个变动目录 1 次列目录 + nfo/海报各 1~2 个请求
- 积压（>12 个信号或 >80 个目录）会退化为整库快速扫描 —— 别攒着不发
- 走 App 既有的扫描队列：有进度、可停止、进程被杀重启续跑；App 没开时信号留云端，下次启动补处理

## 最简实现

```python
import json, datetime, pathlib

signal_dir = pathlib.Path("/你的115挂载/媒体库根/.pad_signal")
signal_dir.mkdir(exist_ok=True)
name = datetime.datetime.now().strftime("%Y%m%d-%H%M%S") + ".json"
(signal_dir / name).write_text(
    json.dumps({"dirs": ["/媒体库根/子目录/ABC-123 示例演员"]}, ensure_ascii=False),
    encoding="utf-8",
)
```

> 往 115 写文件后目录列表约有 45 秒延迟才更新，当轮读不到、下一轮补上属正常。
